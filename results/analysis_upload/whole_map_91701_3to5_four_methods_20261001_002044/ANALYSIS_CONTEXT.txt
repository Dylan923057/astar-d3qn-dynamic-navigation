Purpose: compare four methods across seeds 0-4 using validation only. No test-set results or test-driven method selection.
Map: irregular_workcell_91701; frozen whole-map dynamic_route_pool_v2; 200000 environment steps per run.
Training and validation obstacle counts: 3/4/5 sampled uniformly. Compositions: 3=(1HI,1AR,1BG), 4=equal choice of (2HI,1AR,1BG)/(1HI,2AR,1BG), 5=(2HI,2AR,1BG).
Same seed uses the same episode-indexed environment sampling sequence across methods; episode lengths differ. Start/goal are the original fixed pair (3,3) to (36,36).
All methods/seeds use the same 50 fixed validation scenarios, replayed at each validation checkpoint; fixed_validation_scenarios.json records them.
Pure: no demos. Prefill: one-time pre-training uniform buffer prefill. Time-decay: existing environment-step schedule 25% through step 50000, 10% through step 100000, then 0%. Adaptive: persistent demo replay, initial ratio 25%.
Adaptive uses completed real training episodes in exact 10000-step windows. B=SafeSuccess_all; D=SafeSuccess_conflict; C=min(B,D). Conflict means at least one dynamic conflict opportunity during the episode. If N_conflict<5, C/EMA/ratio stay unchanged. First valid EMA=C; later EMA=0.7*previous+0.3*C. Ratio=0.25*clip((0.95-EMA)/(0.95-0.60),0,1); increases are allowed. Episodes crossing a window boundary are counted in the window where they finish; budget-cut unfinished episodes are excluded. Validation does not control Adaptive.
Validation metrics retain original definitions: safe_success_rate and dynamic_collision_rate are episode fractions; conflict_opportunity_rate and encounter_rate summarize decision-step exposure. Do not interpret validation conflict_opportunity_rate as the Adaptive conflict-episode denominator.
Files per run: training.csv (training episodes), validation_curve.csv (checkpoint summaries), validation_details.csv (checkpoint episode details), result.json (final validation, effective configuration, metadata). Adaptive also has adaptive_schedule.csv; updated=false means C_t/Cbar_t are retained prior values, not freshly estimated abilities.
final_validation_by_seed.csv extracts final metrics without aggregating seeds. implementation/ holds the exact relevant source/config snapshots; inherited config files are included.
Excluded: model weights, duplicated metadata/validation summaries, duplicated final-validation files, machine-specific launch commands, and console logs. Original outputs are unchanged.
Suggested analysis: compare five-seed means and sample standard deviations; plot validation curves by environment steps; report per-seed variability, collision/exposure differences, and Adaptive ratio/ability/low-conflict windows. Inspect the actual curves and explain poor outcomes without assuming Adaptive is better. Treat shared fixed scenarios/checkpoints as correlated observations, not independent experiments; do not select a best checkpoint using test data.
