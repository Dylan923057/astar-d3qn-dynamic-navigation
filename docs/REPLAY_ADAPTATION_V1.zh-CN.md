# 持续回放是否增加动态适应代价：独立实验 v1

此文保留v1协议记录。当前默认入口为 [v2位置均衡版](REPLAY_ADAPTATION_V2.zh-CN.md)，下列不带 `--config` 的命令现运行v2。只有明确复核历史v1时才附加 `--config configs/replay_adaptation_v1.yaml`，两版数据和结果不要混合。

本实验不预设固定示范有害，也不加入新的改进算法。目标是从同一静态学习状态出发，估计继续采样静态 A* 示范对动态适应的**总影响**。已有 Office、clean 和 calibration 实验不变。

## 地图与动态场景

三张新建的 40×40 不规则设备岛地图，种子 91701/91702/91703，障碍由矩形、L、T 形块组成，不要求各分区等密度。起点 `(row=3,col=3)`，终点 `(36,36)`，无孤立自由区。占用率分别约 23.0%、23.0%、23.8%。三图静态最短路均为 66 步，与曼哈顿下界相同；这是有意保留的易学静态基础，不宣称有非单调全局绕行难度。没有米/秒或真实机器人足迹定义，因此是作业区启发的抽象栅格，不是真实机器人部署验证。

- 首先只在 map-index 0 上开发；index 1、2 留作协议冻结后的独立布局复核。
- 每张图 20 条 randomized-tie A* 示范，参考路径就是实际示范的第 1 条。
- 每场仅 1 个主动态障碍，以每环境步一格在 5/7/9 格横穿路线上往返。
- 每图 train/validation/test 为 18/6/12 对，即 36/12/24 个场景；每对共享静态地图、起终点、运动路线和速度，仅改变同一周期运动的初始相位。相位由初始路线索引及方向共同表示。
- control：原样执行参考路径安全。conflict：原样执行参考路径会碰撞，且整组 20 条示范的冲突数严格更多。control 并不保证其他 19 条示范全部安全。
- 每个 conflict 同时有两条已通过实际环境回放的见证：在可见冲突前等待再沿原路通过；局部偏离后在后续最多 10 个参考步内重接原路径。绕行段在决策位置 15×15 范围内，额外步数不超过 8，无重复格。
- 安全最短路由位置×运动相位的时空 A* 计算，使用环境实际规则：下一位置不得占据障碍的旧位置或新位置。规划见证另外在实际环境中逐步回放。
- 等待/绕行是合理选择，不是唯一正确标签；不会因网络选择另一条安全高效路线而判错。
- 三集合的完整动态场景无重复，但允许共享路线几何。本轮是固定地图上的动态适应机制实验，不宣称未见路线泛化或跨地图迁移。
- 接受条件不依赖学习策略的表现；不为了使某方法失败筛图。所选相位、完整场景、见证与审计一起冻结在 manifest 中。

## 同源分叉协议

每个训练 seed 独立得到一个静态 foundation，然后该 seed 的全部比例分支共用它。不同 seed 不共用同一模型。

1. 静态阶段也使用四通道动态环境，但动态障碍为空，使状态编码和转移规则与动态阶段一致。示范动态通道为零。沿用 D3QN 网络、普通 TD 损失，只有静态无效动作被屏蔽。
2. 静态阶段采用固定 25% 示范、最多 300,000 步。至少训练 50,000 步，连续三个间隔 10,000 步的 greedy 检查安全成功，且路径不超过 A* 的 1.15 倍，才合格。固定单起终点的静态 greedy 检查是确定性的，不伪装为多个独立测试样本。
3. 保存 policy、target、Adam 状态、更新计数、全部在线经验、同一示范集、回放 RNG、探索 RNG、Python/NumPy/Torch/CUDA RNG。每个比例分支恢复后计算内容指纹，必须与 foundation 完全相同。
4. 三个分支请求比例为 0%、10%、25%。batch=64 时对应示范/在线为 0/64、6/58、16/48；实际 10% 分支为 9.375%，输出会明确记录。三者在线池容量均为 `10000 - 示范条数`，0% 也不扩容；它叫“停止继续示范回放”，不是从零训练的 Uniform。
5. 各分支在分叉点重新开始环境与障碍时钟，使用相同的动态场景 episode 顺序。策略改变后，episode 长度、走过的状态和接触的场景数量可能不同，这是处理效应的结果，不声称逐步在线样本完全一致。训练日志记录实际场景和动态接触量。
6. 每分支固定 200,000 个环境步，每步一次更新，epsilon 从 0.30 到 0.05，在分叉后 150,000 步内衰减。所有分支使用同一时钟；不再使用会让各方法在不同难度停留不同时间的课程门控。
7. 在 step=0 及此后每 10,000 步进行独立验证和静态保持评估。评估不改变训练环境、网络、经验池或训练 RNG。最终测试只评估固定预算结束的 final model；不按 test 选择模型或停止训练。

奖励在两个阶段及全部分支中固定为 step=-0.01、progress=0.05、stay=0、collision=-1、goal=10。stay=0 表示不额外惩罚等待，等待仍有 step 代价；碰撞立即结束。该协议不与奖励、碰撞语义不同的旧实验混表。

## 判断代价的指标

主要指标是等交互预算下 validation conflict 安全成功率曲线的归一化 AUC。辅助指标包括：

- conflict 安全成功率连续两次达到 90% 的确认步数；未达到记录 null 与右删失标志，不剔除、不伪装成正常达到时间；
- 最终 test 的冲突场景安全率及 control–conflict 失败差；
- 静态保持率；
- 相同冲突位置的危险动作选择率与安全动作 Q 优势；
- 实际接触动态障碍的步数、参考动作存在风险的步数、采样到可见动态经验的次数；
- 示范/在线经验实际采样量，分叉后的更新次数。

固定位置探针通过**实际执行参考安全前缀**恢复障碍时钟、位置和历史帧，然后询问网络的 greedy 动作。它避免把“换路后不再遇到障碍”误判为“学会在冲突处安全反应”。探针为诊断数据，不加入 replay；风险 oracle 不用于控制动作或构造训练监督损失。一阶安全不等于最终成功，因此同时保留完整 rollout 指标。

先在每个 seed 内计算 10%/25% 相对于 0% 的差，再汇总。报告保留所有指定 seed 的静态失败、缺失分支和未达阈值记录。bootstrap 以训练 seed 为单位；只有一个 seed 时不输出置信区间，少于五个 seed 明确标注小样本。即使五个 seed 也应报告效应量、方向和不确定性，而不是只看均值。

若 foundation 不合格，记录为“静态前提未满足”，不启动该 seed 的正式动态分支。配对结果只针对合格 foundation，报告合格率；若大量 seed 不合格，先诊断静态训练，不将其当作动态示范冲突，也不静默替换失败 seed。

结果解释：

- 25% 的适应 AUC更低、达到相同安全水平更慢，且多个 seed 方向一致：支持本条件下持续回放存在适应代价。
- 25% 整体有益但局部探针更差：说明局部代价可能被导航收益抵消，应按层次报告。
- 差异不稳定或固定比例更好：本实验不支持持续回放有害，不能换图直到出现预期排名。
- 控制/冲突场景都差、静态保持也崩溃：先检查一般训练稳定性。
- 动态接触极少：报告低暴露，不能把未观察到差异解释成已证明等效。

此实验估计的是**回放分配的总作用**。25% 同时减少在线样本训练机会；即便发现代价，也尚未区分样本稀释与梯度干扰。那是观察到稳定效应后的机制诊断任务。本轮不提前加入自适应比例或新损失。

## 运行顺序

先在第一张图用两个 seed 做诊断 pilot（会真实训练，请由用户运行）：

```powershell
python scripts/run_replay_adaptation.py --map-index 0 --seeds 0 1 --device cuda
```

也可仅训练并检查静态前提：

```powershell
python scripts/run_replay_adaptation.py --map-index 0 --seeds 0 1 --stage foundation --device cuda
```

确认静态前提与动态暴露后，扩充到五个 seed；已完成、指纹匹配的 foundation/分支自动复用：

```powershell
python scripts/run_replay_adaptation.py --map-index 0 --device cuda
python scripts/summarize_replay_adaptation.py --map-index 0
```

只汇总 pilot 可以附加 `--seeds 0 1`，仍会标注小样本。index 1、2 分别运行同样命令；每张地图独立训练与汇总，不把同一 seed 的多场景当作独立重复。

训练输出：`outputs/replay_adaptation_v1/formal/<map_id>/seed_<n>/`。其中 foundation 保存公共训练状态；demo_00/demo_10/demo_25 保存分叉审计、曲线、测试与模型。汇总位于 `<map_id>/analysis/`，包括逐 seed 表、配对效应、全部 seed 状态和曲线图。

已有结果不覆盖。配置、代码、数据集或设备与旧结果不一致时拒绝混用；改协议时使用新配置/数据版本和新的 `--output-root`。中断目录也保留，不会悄悄当作完成结果。完整 foundation 可按原配置继续启动尚未存在的其他分支；本版本不支持中途恢复一个已部分执行的分支。

流程检查与正式实验分目录：

```powershell
python -m unittest discover -s tests -p test_replay_adaptation.py -v
python scripts/run_replay_adaptation.py --smoke --device cpu
python scripts/summarize_replay_adaptation.py --smoke
```

smoke 将预算缩到每阶段 16 步、网络缩小，并明确绕过静态合格门槛，只检查文件流、恢复和分支；结果标为 smoke_only，**不能用它判断研究假设或地图可学习性**。

本次实现已生成三图与 216 个场景，验收所有配对和安全见证，10 项 unittest 全部通过，CPU/CUDA 的分叉、保存恢复与短流程汇总均通过。正式学习效果尚待用户运行训练。
